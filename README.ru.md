CppDefense превращает CMake-проект на C++ в защиту с ограничением времени:
находит подходящие функции, воспроизводимо выбирает одну из них, скрывает тело,
принимает только тело ответа и запускает CMake, сборку и CTest в изолированной
рабочей копии. В репозитории сохранён локальный CLI и реализована веб-платформа
для студентов, преподавателей и администраторов.

## Основные возможности

- C++23-ядро, интерактивный CLI `cpp-defense` и headless JSON worker;
- детерминированный выбор функций и отдельный workspace для каждой сессии;
- Go Backend с GitHub OAuth, серверными сессиями, CSRF, ролями и проверкой
  доступа к каждому объекту;
- импорт ZIP группы или одной лабораторной с обязательным review и защитой от
  обхода путей и чрезмерного распакованного размера;
- PostgreSQL, неизменяемые версии работ и S3-совместимое хранилище;
- постоянная очередь защит с lease, heartbeat, повторами и аудитом;
- rootless Podman sandbox без сети и с лимитами CPU, памяти, PID, файловой
  системы, времени и логов;
- интерфейс по ролям, анимированное колесо, просмотр замаскированного проекта,
  изменяемая ширина панелей и понятные результаты компиляции;
- C++ CI на Linux, macOS и Windows, а также проверки Go, контрактов и deploy.

## Как проходит веб-защита

1. Преподаватель или администратор загружает ZIP и подтверждает preview.
2. Студент входит через GitHub и начинает защиту неизменяемой версии работы.
3. Runner ищет функции рабочего кода; тесты и build-каталоги не участвуют.
4. Преподаватель подтверждает автоматический или ручной выбор и лимит времени.
5. Runner скрывает выбранное тело, после чего запускается таймер.
6. Ответ вставляется в одноразовую копию и проходит CMake → build → CTest.
   Успех завершает защиту, ошибку можно исправить до дедлайна.

Локальный CLI выполняет аналогичный сценарий для доверенных проектов. Исходный
проект никогда не изменяется.

## Сборка и проверки

Для локального CLI нужны компилятор C++23 и CMake 3.24+:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
```

Сейчас в C++-части **105 CTest-сценариев**. Для Go Backend нужен Go 1.27.1:

```sh
go -C backend test -race ./...
go -C backend vet ./...
node --check backend/webassets/static/app.js
node --test backend/webassets/static/app_test.mjs
```

Полные инструкции: [локальный CLI](docs/ru/USAGE.md),
[Go Backend](backend/README.ru.md) и [развёртывание на VPS](docs/ru/DEPLOYMENT_2.1.md).

## Текущее развёртывание

Документированная небольшая production-схема — один VPS с Ubuntu 22.04,
2 vCPU, 4 ГБ RAM и диском около 120 ГБ для примерно 10–20 пользователей и
одной-двух одновременных проверок:

- Caddy выдаёт HTTPS для `cppdefense.jo-a1.ru`;
- Docker Compose запускает Backend, PostgreSQL и MinIO;
- Go Runner Agent работает как непривилегированный systemd-сервис;
- rootless Podman создаёт одноразовый контейнер на каждую проверку.

Это экономичная, но менее строгая схема, чем отдельный runner: недоверенный код
делит ядро VPS с сервисами. При росте нагрузки или угроз runner надо вынести на
отдельный сервер.
