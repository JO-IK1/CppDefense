## Зафиксированные риски

1. Публичный MinIO OSS-репозиторий архивирован. Последний security-релиз допускается только как временный baseline для alpha/beta. До 2.0 обязателен выбор поддерживаемого S3-совместимого хранилища либо отдельное принятое решение о сопровождении.
2. Домашний ноутбук и Cloudflare Tunnel не дают промышленной доступности. Для первой версии это принятое ограничение; backup и проверка восстановления обязательны до RC.
3. Публичный исходный код не должен содержать архивы студентов, логи, backup, `.env` или рабочие credentials. Проверка должна охватывать всю Git-историю, а не только текущие файлы.

## Проверка контрактов

Локальная проверка выполнена зафиксированными CI-инструментами:

- `check-jsonschema 0.38.0`: четыре schema-файла соответствуют metaschema Draft 2020-12;
- оба manifest-примера и примеры worker request/response проходят схемы;
- fixture с `project_path: ../outside` отклоняется как ожидается;
- `openapi-spec-validator 0.9.0`: `openapi-v1.yaml` корректен как OpenAPI 3.1.

Те же проверки описаны в `.github/workflows/contracts.yml` и запускаются для каждого изменения каталога `contracts/`.

## Внешние действия перед полным закрытием этапа

- закоммитить и опубликовать подготовленную смену лицензии в основном репозитории; правообладатель — Zakharev Georgii, прежние MIT-права сохранены, граница перехода описана в его `docs/LICENSING.md`;
- проверить всю Git-историю на secrets и персональные данные;
- включить GitHub secret scanning, push protection и Dependabot;
- добавить CI-проверку лицензий зависимостей после появления файлов зависимостей Go/C++/frontend;
- заменить placeholder `cppdefense.example` после выбора постоянного домена.

Этап 1 и Этап 2 можно начинать параллельно после переноса этих контрактов в основной Git-репозиторий. Полностью закрывать Этап 0 следует только после выполнения внешних действий выше.
